# SAR 實戰模擬分頁計劃

## 目的與範圍

新增「實戰模擬」分頁，依每日 SAR 選股與資金管理規則，用歷史日線模擬每日訊號、進場、加碼、出場與資金占用情況。

此模擬帳戶與真實庫存清單分開，避免模擬交易污染使用者實際持股資料。策略計算應放在 `src/`，PySide6 分頁負責操作與呈現；之後如要讓 Streamlit 顯示相同結果，可重用同一套核心邏輯。

## 目前架構與差異

- 專案以本機 PySide6 桌面版為主要操作介面，Streamlit 為可選前端。日線資料、選股、技術指標與資料存取已有分層，可參考 `README.md`、`ai/PLAN.md`。
- 桌面版使用 `QTabWidget`，並在切換分頁時刷新內容；可沿用 `desktop/main_window.py` 的分頁組裝與 `_on_tab_changed()` 刷新模式。
- 日線 OHLCV 存於主資料庫，SAR 計算已有 `src/indicators/parabolic_sar.py`。
- **SAR 不需要另寫演算法**：`src/indicators/parabolic_sar.py` 的 `compute_sar()` 已能依 OHLC 計算每日 SAR 多空狀態與 SAR 數值，`sar_flip_days_ago()`／`sar_flipped_within()` 也已能判斷近期翻多。新策略應重用這些函式；歷史選股仍需針對每檔股票、截至每個歷史交易日的資料，取得該日 SAR 狀態、翻多天數與 SAR 距離，不能用今天計算的結果回填歷史日期。
- 現有 `src/backtest/engine.py` 是單股、單一持倉的簡化回測引擎，沒有多檔共同資金池、一次加碼與每日全市場選股機制；回測結束時也會強制平倉。因此不宜直接用它承載本策略的投資組合模擬。
- 使用者提供的 `sar_daily_runner.py`、`sar_backtest.py`、`database/storage.py`、`config/scanner_settings.json` 目前不在此 repo 中。新實作前需以本計劃列出的規則為規格，不假設那些檔案已存在。

## 策略規格

### 每日選股

每日收盤後最多選出一檔；訊號日為 D 日，下一交易日才進場。

#### 第一層：SAR 多頭基本篩選

參數來源原規劃為 `config/scanner_settings.json`，但目前 repo 找不到該檔案。首版實作前需決定這些值要新增為設定，或先採用以下規格：

| 條件 | 規格 |
|---|---|
| SAR 狀態 | 多頭 |
| SAR 翻多天數 | `flip_days_ago <= 1` |
| 收盤價 | 高於 200 日均線 |
| 均線排列 | MA5 > MA10 > MA20 |
| BIAS(200MA) | ≤ 999%（等同不限制） |
| 無上方壓力區 | 收盤價高於 MA60、MA120，且分別高於各均線至少 3% 的收盤價比例；即 `(close - MA60) / close > 3%` 且 `(close - MA120) / close > 3%` |
| SAR 距離 | 絕對值小於 35% |
| 成交量 | 至少 10 張 |

#### 第二層：策略追加條件

| 條件 | 規格 |
|---|---|
| SAR 距離 | -15% 至 0% |
| 成交量 | 至少 1,000 張 |
| 收盤價 | 不高於 NT$100 |
| 當日 K 棒 | 收紅，收盤價 > 開盤價 |
| 排序 | 依 `|SAR 距離%|` 由小到大，只取第 1 名 |

股價資料庫的成交量單位是「股」，策略規格以「張」表示；換算時 1 張 = 1,000 股。因此 1,000 張應換成 1,000,000 股，10 張應換成 10,000 股。實作與測試需明確鎖定單位，避免誤用門檻。

### 進場

- 訊號日收盤後產生選股結果。
- 下一交易日以當日最高價作為保守假設的買進價。
- 初始每筆投入 NT$10,000，股數為 `floor(10,000 / 買進價)`。
- 現金不足時跳過該訊號，不排隊、不延後買進。

### 持倉管理與出場

每日依以下順序檢查；進場當天不執行出場檢查：

1. **加碼一次**：當日最低價觸及原始買價的 85% 時，以原始買價 × 0.85 加碼 NT$5,000，重新計算持倉均成本。
2. **停損**：當日最低價觸及均成本的 80% 時，以均成本 × 0.80 出場。
3. **移動停利啟動**：持有期間最高價達均成本的 116% 時，啟動移動停利，不立即出場。
4. **移動停利出場**：移動停利啟動後，若當日最低價觸及「峰值報酬率減 3 個百分點」對應的均成本報酬價位，則以該價位出場。此 3% 是相對均成本的百分點；例如峰值報酬 +20%，出場價為均成本的 +17%。

不設定持有天數上限。模擬區間結束仍持有的部位不強制平倉，需列為未平倉，並以最新可用收盤價計算未實現損益。

### 交易成本與本金

- 初始本金：NT$100,000。
- 初始每筆投入：NT$10,000。
- 一次加碼投入：NT$5,000。
- 買進、加碼及賣出都計入手續費，費率 0.1425%，最低 NT$20；買進／加碼手續費納入現金支出與持倉成本。
- 證交稅：0.3%。
- 賣出時計入手續費與證交稅，計算已實現損益時從成交金額扣除兩者。

## 建議實作設計

### 1. 策略專用選股器

新增專用的歷史選股流程，逐交易日計算或取得該日所需的 SAR、均線及其他篩選欄位，依序套用兩層條件。每個訊號日最多保留一檔，排序規則固定為 `|SAR 距離%|` 由小到大。

不可直接假設既有 `daily_candidates` 與本策略選股條件完全相同；若要重用，需先逐項確認條件、資料日期與單位一致。

### 2. 獨立投資組合模擬引擎

新增能跨股票逐交易日推進的模擬流程，管理一個共用現金帳戶與多筆同時持有的部位。每筆部位至少需保存：

- 股票代號與名稱。
- 訊號日、進場日與進場價。
- 原始買進股數、原始買價。
- 加碼日期、加碼股數、加碼價與是否已加碼。
- 均成本。
- 移動停利是否啟動、持有期間峰值。
- 出場日期、出場價與出場原因（如已出場）。
- 已實現或未實現損益。

依交易日推進時，先處理既有持倉的加碼／出場，再按該日應執行的前一交易日訊號嘗試進場；同日出場回收的現金可供該日新進場使用。此順序依使用者確認採用，並以測試固定下來。

日線 OHLC 無法還原同一天內最高價與最低價的先後順序。為避免使用當日新高回頭影響當日可能已觸發的移動停利，依保守假設：先使用前一日已記錄的峰值判斷當日是否出場；若未出場，再用當日最高價更新峰值，供之後交易日使用。

### 3. 模擬資料隔離與可重算性

- 模擬交易資料不得寫入真實庫存資料。
- 使用獨立的本機 SQLite 資料庫或明確隔離的資料表儲存模擬設定、每日選股、成交紀錄、現金流水與持倉狀態。
- 保存策略版本及模擬最後處理日期，避免重跑造成重複交易或重複扣款。
- 提供可重算能力；重算時應明確處理舊模擬結果，不能在既有結果上默默重複累加。

### 4. 實戰模擬分頁

初版畫面建議包含：

- 模擬日期區間與重新計算操作。
- 本金、目前現金、投入成本、持倉市值、已實現損益、未實現損益與總資產。
- 目前持倉清單，呈現股數、均成本、加碼狀態、停利狀態、未實現損益與持有天數。
- 模擬事件紀錄：每日選股、進場、加碼、停損、移動停利出場、現金不足跳過。
- 結果區以子分頁分開顯示目前持倉、已實現損益明細及模擬事件；已平倉明細列出進出場日期、均成本、出場價、扣除成本後的損益及出場原因。
- 模擬本金與選股收盤價上限可在桌面版手動輸入；結果摘要下方另行顯示總報酬率，非負為紅色、負值為綠色。
- 交易單位可切換零股／整張：零股模式維持初始 NT$10,000、加碼 NT$5,000 預算；整張模式每次進場 1 張、最多加碼 1 張，現金不足以支付整張成交金額與費用時跳過該筆，不延後買進。
- 未平倉部位不得當作已實現交易，也不得在模擬結束時自動賣出。

核心策略與資金計算留在 `src/`；桌面 UI 不直接承擔選股或損益邏輯。

## 階段一：歷史回測

**目的：把同一套固定規則分別放到兩段歷史行情中重跑，查看模擬績效在不同期間有何差異。**這能幫助了解規則是否只在某一段行情表現較好，但不能證明未來一定有效，也不是預測未來報酬。

- 畫面名稱使用「歷史回測」，期間欄位使用「較早期間／較近期期間」，避免使用容易被誤認為完全獨立的「樣本外」術語。
- 依可用行情日期保留 240 個交易日作指標暖身，再預設以前 70% 為較早期間、後 30% 為較近期期間；使用者可調整兩段日期，但較早期間必須早於較近期期間且不可重疊。
- 兩個期間以相同本金與同一組策略參數各自從頭建立模擬帳戶，並非連續持有，也不把前段現金或持倉延續至後段。
- 讀取截至較近期期間迄日的現有 OHLCV，在記憶體重算均線與 SAR，沿用既有指標算法，不依賴可能不完整的 `daily_indicators` 快取，也不寫入主行情資料庫。
- 顯示兩期的訊號數、已平倉數、勝率、已實現／未實現損益、總報酬率、最大回撤及平均資金投入率；另保存並顯示較近期期間每日現金、持倉市值、總資產與回撤。
- 現金基準為 0%（不計利息）；每次比較及後段資產曲線保存於獨立模擬資料庫。
- 必須揭露資料未包含完整已下市股票、未還原除權息的限制，以及較近期期間包含曾用於規則比對的日期。比較結果受資料限制影響，不能視為無偏的未來預測。

## 階段二：未來情境推演

**目的：使用者每次選擇一種真實歷史行情片段，轉成假設的未來價格路徑並列出策略可能選中的股票；不是預測未來，也不估計情境發生機率。不同情境互斥，不能視為會在同一期間同時發生。**

- UI 以情境下拉選單提供「大盤漲幅較大／大盤接近平盤／大盤跌幅較大」三種路徑；每次只推演所選的一種，不把三種績效／選股混在同一批結果。
- 起始帳戶接續最近一次「策略模擬」結果，保留期末現金、行情截至推演起點當日的未平倉部位與最後交易日的待進場訊號，不另開本金；舊模擬結果不得因推演而被修改。行情落後推演起點的未平倉部位不納入推演資產或持倉，並在結果中列出股票、最後行情日、股數、市值及排除原因。
- 可選 20、60 或 120 個交易日。依截至起始日可用的加權指數日線，找出所選類型、等長且與其他類型不重疊的歷史區間。
- 對行情日期等於推演起點且具有來源行情的股票，將選定歷史片段中個股每日 OHLC 相對上一個來源收盤價的比例路徑縮放到目前股價；成交量沿用來源日，均線與 SAR 由來源行情重算後按價格比例縮放。不得將舊行情當作目前報價延續推演。
- 以策略原有規則和相同資金／交易模式，在所選情境的假設未來日期掃描目前股池，逐日執行選股、持倉管理、進場、加碼與出場。主要輸出應是該次情境的候選明細，至少列出訊號日、預計進場日、股票代號／名稱、預計進場價、預計股數及資金是否足夠；情境績效及每日資產曲線作輔助資訊。
- 推演日期排除週末及 `src/data/trading_calendar.py` 提供的 TWSE 已公告年度休市日；未公告年度仍只能以週一至週五估算。股票清單與行情可能不完整，且行情未還原除權息／分割。對無法與目前報價對應的股票不推演。
- 結果與每日資產曲線存於獨立模擬資料庫，不寫回主行情資料庫或真實庫存；需保存所接續的策略 run ID 與歷史來源區間，便於辨識結果依據。
- 策略模擬與未來情境推演顯示期末投組時，若未平倉股票最後行情早於模擬迄日／推演起點，須從目前持倉與期末資產計算排除，並標示股票、最後行情日及被排除市值；僅建立顯示用副本，不刪除或改寫資料庫中的原始模擬紀錄。

## 測試清單

使用合成 OHLCV 與可控訊號建立單元測試，至少涵蓋：

- 隔一個交易日才進場，並以進場日最高價成交。
- 每個訊號日最多選一檔，且排序取 `|SAR 距離%|` 最小者。
- 成交量股數／張數換算及各篩選邊界。
- 股數向下取整；現金不足時跳過且不排隊。
- 同時持有多檔時共用現金正確扣款。
- 加碼門檻依原始買價計算，且每筆持倉最多加碼一次。
- 加碼後均成本與後續停損價正確更新。
- 移動停利啟動條件、以前一日峰值判斷當日出場、未出場時再更新當日峰值，以及「峰值報酬減 3 個百分點」出場價。
- 同日多個條件都觸發時，依規定順序執行，並避免對已出場部位重複處理。
- 手續費最低金額、證交稅與買進費用假設正確。
- 模擬期間結束後未平倉部位保留，未實現損益與總資產正確。
- 重算或續跑不會產生重複交易與重複現金流水。
- 模擬資料與真實庫存資料互不影響。
- 每日資產快照日期完整且期末資產與投組結果一致。
- 指標可只用歷史 OHLCV 重算；不依賴快取、不讀未來資料、不修改行情資料庫。
- 較早期間與較近期期間嚴格按時間排列、不可重疊，且以相同本金各自重新計算。
- 兩段期間績效指標及後段資產曲線計算、持久化與載入一致。
- 三種行情來源區間長度相同且彼此不重疊，並正確涵蓋大盤上漲、接近平盤與下跌路徑。
- 個股歷史 OHLC 以來源前一日收盤價為比例基準縮放到目前價格，未來路徑不改寫來源行情。
- 情境帳戶正確接續模擬期末現金、未平倉及最後待進場訊號；第一個推演日會管理既有部位，且不修改基準 run。
- 行情早於推演起點的持倉會從情境帳戶及推演資產中排除，列出最後行情日與被排除市值；原始策略模擬紀錄保持不變。
- 所選情境的交易結果、每日資產曲線可保存及還原；不存在有效歷史路徑時要明確顯示錯誤，不得以成功形狀的空結果代替。
- 各情境每日選出的股票都能呈現訊號日、預計進場日、股價、股數及資金狀態；包括已進場、資金不足略過、行情缺失，以及訊號發生於推演最後一日等狀態。
- 選定單一情境後只載入、執行及顯示該情境，不應同時計算或列出其他情境。

## 已確認的實作決定

- **SAR 計算**：重用既有 `src/indicators/parabolic_sar.py`，不另寫 SAR 演算法；策略會按歷史日期取得對應的 SAR 結果。
- **參數放置**：第一版將固定篩選參數集中寫在 SAR 策略程式內，不新增設定檔，也不影響全系統選股設定。未來若需要使用者自行調整，再另行設計 UI 與設定儲存。
- **無上方壓力區**：收盤價都必須高於 MA60、MA120，且股價與各均線差距各自超過收盤價的 3%；公式為 `(close - MA) / close > 0.03`。任一均線不在收盤價下方或距離未超過 3%，即不符合此條件。
