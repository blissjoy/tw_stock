- **解讀**: 外部工具原文的「三維過濾法」：判斷任何一檔股票，只需要動態問自己三個問題——①現在的價格在幹嘛？（上漲／下跌／突破關鍵點／盤整？）鎖定Q1；②今天的成交量給不給力？（量增／量縮／量平？）鎖定Q2；③這檔股票現在在哪裡？（均線基期高檔／低檔／全基期？）鎖定Q3。三個答案交叉出的組合，對應到12種(實際上because部分格子依基期再細分a/b兩種解讀，共19種)具名矩陣格，見R-Q3M-01~19。本檔只定義三個維度各自「怎麼算」，讓底下19個矩陣格規則共用，不必每條各自重複定義一次，跟R-TREND-01(轉折波定義)是後續多筆趨勢判定規則共用輸入的角色相同。
- **可程式化**: 部分——Q1/Q2兩軸可完整程式化；Q3軸目前只能做到「高檔／低檔／全基期」三態，PDF原文部分矩陣格用到的「初升段／主升段／末升段／末跌段／初跌段／多頭回檔期／空頭主跌段」等更細的子階段，本專案沒有對應的分類器，見下方計算公式的說明。
- **所需資料**: 收盤價、開盤價、最高價、最低價、成交量、5日均量
- **計算公式**:
```
# Q1：價格方向(4態)——「關鍵點」優先判斷(當天觸及/穿越一個明確技術關鍵價位)，
# 其次看漲跌方向，都不成立才算盤整。「關鍵點」目前沿用本專案既有的各種突破/跌破
# 事件旗標(不重新定義新的關鍵點判斷)：
#   R-CANDLE-04 detect_consolidation_breakout()的breakout_up/breakout_down
#   R-SR-01/02 突破/跌破轉折高低點
#   R-LINE-11/12/14/15 切線/軌道線突破跌破
#   R-GAP-01 detect_gap()當天出現缺口
def classify_q1_price(breakout_up, breakout_down, close_t, close_t_minus_1):
    if breakout_up or breakout_down:
        return "關鍵點(向上突破)" if breakout_up else "關鍵點(向下跌破)"
    if close_t > close_t_minus_1:
        return "上漲"
    if close_t < close_t_minus_1:
        return "下跌"
    return "盤整"  # 平盤，且沒有觸及任何關鍵點

# Q2：成交量方向(3態)——沿用R-VOLPRICE-01既有的MA5倍數門檻，不重新發明新門檻：
#   量增 ≈ 攻擊量/爆大量(Volume >= 1.2倍MA5_vol)
#   量縮 ≈ 止跌量等級(Volume <= 0.5倍MA5_vol)
#   量平 = 介於兩者之間
def classify_q2_volume(volume_t, ma5_vol_t):
    ratio = volume_t / ma5_vol_t
    if ratio >= 1.2:
        return "量增"
    if ratio <= 0.5:
        return "量縮"
    return "量平"

# Q3：基期位置——沿用src/indicators/trend_position.py既有的compute_trend_position()
# 二元判斷(is_at_high/is_at_low)，只能到「高檔/低檔/全基期(不高不低)」這一層：
def classify_q3_position(is_at_high_t, is_at_low_t):
    if is_at_high_t:
        return "高檔"
    if is_at_low_t:
        return "低檔"
    return "全基期"

# ⚠️ PDF原文部分矩陣格用「初升段/主升段/末升段/末跌段/初跌段/多頭回檔期/空頭主跌段」
# 這種比「高檔/低檔」更細的子階段描述，這是rule_scan.py docstring本來就明講的既有缺口
# (is_bull_early_or_main_stage/is_start_of_decline/is_late_stage_rally等函式本專案
# 尚未提供)——這裡的R-Q3M-01~19只能程式化到「高檔/低檔/全基期」三態，PDF原文的子階段
# 字眼保留在「解讀」欄位對照書中概念，但「計算公式」欄位不假裝能判斷到那麼細。
```
