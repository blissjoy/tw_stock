# 借殼股6特徵篩選清單

- **Rule ID**: R-CHIP-06
- **名稱**: 借殼股「6特徵」預先鎖定篩選清單
- **分類**: 籌碼面
- **原文與頁碼**: `ai/ebook-summary-chen/P06-C3-舊瓶裝新酒借殼上市搏翻身.md`（第6篇第3章「舊瓶裝新酒 借殼上市搏翻身」，p.217-218）
- **解讀**: 書中評為「全書唯一一套完全不依賴分點/籌碼資料、只用標準財務資料就能完整程式化的篩選清單」。借殼上市在市場上不透明，等到消息走漏才進場已經太慢，但通常被選中借殼的公司會有6大共通特徵：(1) 股價≤10元（跌破票面值）；(2) 股本≤10億元（籌碼輕、好談交易）；(3) 近3年沒什麼獲利甚至小虧；(4) 近3年沒有配發現金/股票股利；(5) 大股東持股比重高，5成以上最好談，低於3成不易蒐集籌碼；(6) 符合以上條件的公司，若先辦減資、再辦私募增資引進特定股東（股權會被鎖3年），來借殼的可能性大增。書中也提醒借殼目的分正面（新東家經營健康、獲利改善）與負面（灌業績做股價，如基因/胖達人事件）兩種，但這部分需要額外的公司治理/新股東背景調查，純量化規則無法涵蓋，只能作為輔助提醒。核心進場時機建議：不用太早進場，觀察減資公告前後是否有高手/贏家券商(R-CHIP-28/30)進場，有的話勝算更高。
- **可程式化**: 部分——6項特徵裡，(1)股價、(2)股本、(3)近3年獲利、(4)近3年股利、(6)減增資公告這5項的資料源都已查證可用（見下方所需資料），組合成篩選清單的邏輯本身不複雜；(5)大股東持股比重理論上可用`holder_shares_distribution`表（`>1,000張`級距）近似，但書中的「5成以上」門檻是「大股東」整體持股比重，需要額外加總計算(集保資料只有分級距的人數/股數/佔比，若同一大股東分散在多個帳戶，用單一級距占比可能低估)。「借殼目的正面/負面」這半段完全無法程式化，只能當人工複核提醒。
- **所需資料**: 股價、股本（TWSE OpenAPI `/opendata/t187ap06_X_*`資產負債表可取得，本專案尚未串接）、近3年獲利（TWSE OpenAPI `/opendata/t187ap07_X_*`綜合損益表，尚未串接）、近3年股利（同上或另有股利公告資料源，尚未串接）、大股東持股比重（`holder_shares_distribution`表，本專案已有且有FinMind `fetch_holding_shares_per()`抓取函式，見R-CHIP-07）、減資後私募增資公告（`mops_capital_changes`表，已有但只到「哪個月增減資」，看不出是否為「先減資後私募增資」的組合模式，且私募本身可能需要另一份MOPS報表才能確認）。
- **計算公式**:
```
function reverse_merger_candidate_score(stock, t):
    conditions = {
        "低價": close[t] <= 10,
        "小股本": share_capital[t] <= 10e8,
        "近3年無獲利": all(eps[year] <= 0 for year in last_3_years),
        "近3年無股利": all(dividend[year] == 0 for year in last_3_years),
        "大股東集中": whale_holding_pct[t] >= 0.5,  # >=0.3也列入觀察名單
        "減資後私募增資": has_capital_reduction_then_private_placement(stock, t),
    }
    score = sum(conditions.values())
    return score, conditions  # 全部符合(6/6)才是最強嫌疑名單，5/6可列入次要觀察
```
- **參數**: 股價門檻10元、股本門檻10億、大股東持股門檻50%(次要門檻30%)皆為書中明確數字；「近3年」的獲利/股利觀察期間也是書中明確數字。
- **可回測**: 部分——財務類條件((1)~(5))可回測「符合條件的股票後續是否真的被借殼+股價表現」；(6)「減資後私募增資」這個時序條件需要MOPS私募公告資料，目前還沒有，無法一併回測完整的6項組合規則，只能回測前5項的篩選效果。
- **信心**: 55/100 中（書中給出的6項特徵條件本身非常具體、明確，理應給高分；但扣分原因是本專案目前完全沒有串接股本/獲利/股利這3項基本面資料，`daily_pipeline.py`目前只抓價格，這條規則實質上還沒有任何一行程式碼實作，且「先減資後私募增資」的時序判定資料源也還沒確認，距離「可執行」還有一段距離）。
