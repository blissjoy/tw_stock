# 高手型主力辨識法

- **Rule ID**: R-CHIP-28
- **名稱**: 高手型主力辨識法（推手戰術＋庫藏股執行券商線索）
- **分類**: 籌碼面
- **原文與頁碼**: `ai/ebook-summary-chen/P03-C3-高手型易賺投資財.md`（第3篇第3章「高手型 易賺投資財」，p.108-113）
- **解讀**: 5大主力分類之一。每檔股票都會有「最了解它」的高手券商——股價往上攻時，抓出持股最多、布局價位相對低的券商，就是該股高手。特徵：花長時間布局，然後拉抬，最後出貨，每次該股發動幾乎不缺席。**「推手戰術」**：吃貨階段大量買進後，拉抬階段不再大幅加碼，只在關鍵價位敲大單幫助突破，藉此吸引技術面投資人進場，同時保留資金實力、避免高點賣不完(上銀案例)。分類邊界：跟公司派的區別是地緣性——若某券商跟公司所在地不同卻長期對某股操作精準，代表是「市場派高手」（跟公司派靠內部消息不同，市場派高手靠對籌碼/技術面的精準判斷）。**新資料來源線索**：公司庫藏股執行券商是依證交法規定須公告的公開資訊，可交叉比對分點資料找出重要操盤分點，即使庫藏股結束後該分點仍可能持續是重要玩家(東貝案例)。重要限制：高手券商是「個股專屬」的，不能跨股票套用同一份名單。
- **可程式化**: 部分——庫藏股執行券商公告理論上可用`src/data/mops_client.py`的MOPS存取方式抓取（2026-08-09已確認MOPS的`/mops/api/redirectToIRB`可透過Playwright存取，但庫藏股公告對應哪個`fileNoOfIRB`報表代碼還沒查證，目前只確認了`IRB160`公司增減資表可用），一旦確認可作為「該股重要操盤分點」的線索來源，不需要`broker_chips`就能先建立一份候選名單；但「推手戰術」量能特徵判定(拉抬階段庫存不增加、只在關鍵價位敲大單)以及「布局價位相對低」的完整辨識，仍需要`broker_chips`表（待FinMind付費方案）。
- **所需資料**: 公司庫藏股執行券商公告（MOPS，報表代碼待查證）、個股每日各券商分點買賣張數與庫存（`broker_chips`表，待FinMind付費方案）、公司地址vs券商地址（同R-CHIP-27，用於區分市場派高手vs公司派）。
- **計算公式**:

function treasury_stock_broker_lead(stock):
    # 一旦MOPS庫藏股公告報表確認可抓，可直接列為候選高手券商，不需broker_chips
    return get_treasury_stock_execution_broker(stock)  # 待MOPS報表代碼查證

function accumulation_then_key_level_push(stock, trader, accumulation_period, markup_period):
    accumulation_net_buy = net_position_change(stock, trader, *accumulation_period)  # 待broker_chips
    markup_net_change = net_position_change(stock, trader, *markup_period)
    large_orders_at_key_levels = count_large_orders_near_resistance(stock, trader, markup_period)
    return accumulation_net_buy > 0 and abs(markup_net_change) < small_threshold and large_orders_at_key_levels > 0

function stock_specific_expert_broker(stock, trader):
    # 高手券商是個股專屬，需個股-券商配對資料結構，不能用全域名單
    return trader_historical_accuracy(stock, trader)  # 待broker_chips長期資料

- **參數**: 「關鍵價位」的判定標準書中沒給，可考慮跟`ai/zhu-rules/支撐壓力`既有規則對照；「敲大單」的量化定義(單筆多少張)也未給。
- **可回測**: 否——庫藏股公告子條件即使查證到位也只是候選名單，完整規則驗證仍需`broker_chips`，目前無法回測。
- **信心**: 30/100 低（庫藏股執行券商是全書少見「有法定公告義務」的新資料來源線索，值得優先查證；但扣分原因是完整的高手券商辨識仍需要`broker_chips`，且庫藏股公告本身在MOPS的確切報表代碼還沒查證到位，只是「理論上可行」而非「已確認可行」）。
