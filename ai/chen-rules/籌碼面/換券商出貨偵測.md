# 換券商出貨偵測

- **Rule ID**: R-CHIP-13
- **名稱**: 換券商出貨偵測（含資金轉移追蹤）
- **分類**: 籌碼面
- **原文與頁碼**: `ai/ebook-summary-chen/P05-C3-破解主力手法狡兔三窟操控.md`（第5篇第3章「破解主力手法 狡兔三窟操控」，p.186-192）
- **解讀**: 書中評為「全書方法論最嚴謹的偵探式多資料源交叉驗證案例」（黑松→農林）。核心手法有兩種：(1) **換券商出貨**——主力在A券商分點大買，卻在「過去從未買進過」的B券商分點賣出，因為換券商出貨在台灣市場不常見（融資股票是抵押品不能輕易匯出、培養信任的交易員也不容易），一旦發生代表刻意規避追蹤。偵測邏輯：`(賣方券商過去交易史近乎無買進紀錄) + (賣出量異常龐大，需搭配集保股權分散表R-CHIP-07驗證規模合理性——只有持股1,000張以上的大咖才可能賣出這麼多) + (身分背景不合理，如外資與本土券商同時大量賣出冷門股)`。黑松→農林案例還進一步用「該資金後續是否轉戰其他股票、與其他可疑分點重複出現」確認身分——巧合一次是巧合，巧合兩次以上就是同一組操盤資金的證據，這也直接回收解答了R-CHIP-09「假外資偵測」裡農林(2913)那個懸而未解的案例。(2) **分點控盤/左右手互倒**——一批券商只買不賣、另一批只賣不買、且每日成交量偏低，代表大股東或主力在用不同券商創造假的交易活絡假象，其實籌碼都是自己的，這個手法資料需求較低，只需要分點買賣方向。
- **可程式化**: 否——兩種手法都需要「個股×券商分點×逐日買賣方向與張數」的歷史（`broker_chips`表，待FinMind付費方案），換券商出貨手法還需要額外搭配`holder_shares_distribution`表（已有）驗證規模合理性，以及跨股票追蹤（同一批可疑券商是否在不同股票上重複出現）。分點控盤/左右手互倒的資料需求相對單純（只需買賣方向，不需要集保驗證），一旦`broker_chips`到位可以優先實作這一半。
- **所需資料**: 個股每日各券商分點買賣張數與方向（`broker_chips`表，待FinMind付費方案）、集保股權分散表（`holder_shares_distribution`表，已有，用於規模合理性驗證）、跨股票的可疑券商重複出現追蹤（需要建立「券商-個股」歷史事件資料庫，目前沒有）。
- **計算公式**:
```
function switched_broker_selloff(stock, sell_trader, t, lookback_days=250):
    history = broker_chips[stock][sell_trader][t-lookback_days : t]
    never_bought_before = all(row.buy == 0 for row in history)
    sell_volume = broker_chips[stock][sell_trader][t].sell
    reasonable_only_for_whale = sell_volume / total_shares_outstanding(stock) > whale_holding_threshold
    return never_bought_before and reasonable_only_for_whale

function left_hand_right_hand_control(stock, t, window=20):
    traders = broker_chips[stock][t-window:t]
    only_buy = [tr for tr in traders if all(r.sell == 0 for r in tr.rows)]
    only_sell = [tr for tr in traders if all(r.buy == 0 for r in tr.rows)]
    low_volume = avg_daily_volume(stock, t-window, t) < historical_avg_volume(stock)
    return len(only_buy) > 0 and len(only_sell) > 0 and low_volume
```
- **參數**: 「賣出量異常龐大」「過去交易史近乎無買進」「巧合兩次以上」皆為定性描述，書中沒有給出精確數字門檻，需自行設計並回測。
- **可回測**: 否——`broker_chips`資料源未到位，無法回測。
- **信心**: 30/100 低（黑松→農林案例展示的方法論品質是全書最高等級之一，多資料源交叉驗證邏輯嚴謹；但扣分原因是核心資料`broker_chips`未到位，且「巧合兩次以上」這種跨股票關聯偵測的工程實作難度也不低，需要額外建立長期追蹤的資料結構，不是單純的門檻判斷）。
