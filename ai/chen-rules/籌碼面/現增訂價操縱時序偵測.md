# 現增訂價操縱時序偵測

- **Rule ID**: R-CHIP-22
- **名稱**: 現金增資訂價操縱時序偵測
- **分類**: 籌碼面
- **原文與頁碼**: `ai/ebook-summary-chen/P07-C4-凶狠新鉅科主力完美操控.md`（第7篇第4章「凶狠新鉅科 主力完美操控」，p.261-263）
- **解讀**: 書中評為「全書唯一針對現增操縱的完整量化案例」。台灣現金增資的法定訂價公式：以公告日往前1、3、5個營業日股價平均值打85折計算發行價（新鉅科案例：3日均價105.3元×85折＝90元）。核心操縱手法：`(公司公布現金增資計畫，訂價窗口為公告前1/3/5營業日) + (訂價窗口前數個交易日出現利多消息/財報公告，股價急拉) + (該股主要券商的持股/收購行為恰好在此期間停止或轉折)` → 高度懷疑是刻意拉抬股價、墊高增資訂價基準的操縱行為。新鉅科案例：訂價窗口前公告月營收創51個月新高（年增307.95%），股價同時由90元拉抬至110元以上，最後定價90元恰好和主要券商停止收購的價位吻合，形成「印股票換鈔票」的完整利益結構。
- **可程式化**: 部分——現增訂價公式本身(前1/3/5日均價×85折)完全可程式化，且月營收公告已確認可用（TWSE OpenAPI `/opendata/t187ap05_P`），股價資料已有；缺口在於「現金增資公告與訂價期間」這個公開資訊觀測站(MOPS)重大訊息公告，尚未逐一查證對應的報表代碼（`mops_capital_changes`表目前只涵蓋IRB160「公司增減資表」，看得出「哪個月增減資」但看不出「現金增資的具體訂價窗口」）；「主要券商持股行為在此期間停止/轉折」需要`broker_chips`表（待FinMind付費方案）。三個條件裡月營收時序條件可以先做，其餘兩個仍有缺口。
- **所需資料**: 現金增資公告與訂價期間（MOPS，需要比`mops_capital_changes`現有的IRB160更詳細的報表，報表代碼待查證）、月營收公告日期與數字（TWSE OpenAPI `/opendata/t187ap05_P`，已確認可用但本專案未串接）、股價（已有）、主要券商持股行為（`broker_chips`表，待FinMind付費方案）。
- **計算公式**:
```
function private_placement_pricing_formula(stock, announce_date):
    prices_1_3_5 = [close[stock][trading_day_before(announce_date, n)] for n in (1, 3, 5)]
    avg_price = mean(prices_1_3_5)
    return avg_price * 0.85  # 法定85折公式，跟MOPS公告的實際定價比對即可驗證

function pricing_manipulation_flag(stock, pricing_window_start, pricing_window_end):
    revenue_surprise = has_positive_revenue_surprise(stock, pricing_window_start)  # 月營收，已確認可用
    price_rally = (close[pricing_window_end] - close[pricing_window_start]) / close[pricing_window_start] > threshold
    main_broker_paused = main_broker_activity_stopped(stock, pricing_window_start, pricing_window_end)  # 待broker_chips
    return revenue_surprise and price_rally and main_broker_paused
```
- **參數**: 訂價窗口1/3/5營業日、85折為法定明確數字；「股價急拉」的漲幅門檻書中沒有給出精確數字，需自行設定。
- **可回測**: 部分——訂價公式本身+月營收時序條件可以先回測（不需要`broker_chips`）；但要驗證完整規則(含券商停止收購)需要等分點資料到位。
- **信心**: 40/100 低中（訂價公式是法規明確公式，月營收資料也已確認可用，這部分可程式化程度高；扣分原因是現增公告本身的MOPS報表代碼還沒查證，且「主要券商停止收購」這個關鍵佐證條件仍卡在`broker_chips`，完整規則距離可執行還有落差）。
