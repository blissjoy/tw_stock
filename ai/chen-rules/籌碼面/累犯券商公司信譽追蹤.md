# 累犯券商公司信譽追蹤

- **Rule ID**: R-CHIP-23
- **名稱**: 「累犯」券商/公司信譽追蹤
- **分類**: 籌碼面
- **原文與頁碼**: `ai/ebook-summary-chen/P07-C4-凶狠新鉅科主力完美操控.md`（第7篇第4章「凶狠新鉅科 主力完美操控」，p.263）
- **解讀**: 新鉅科案例回溯發現：2010年上漲時，元大寶來大甲同樣是主要買進券商，且同樣在最高點大量出貨；2013年再度上演相同劇本（買進→拉抬→現增操縱→出貨），證實這是「累犯」。核心規則：**同一批券商分點在同一檔股票上，若過去已出現過「最高點大量出貨後股價腰斬」的紀錄，之後若該股票再度出現同一批券商大量買進、股價又拉抬，應對其後續可信度打折扣，優先假設是同一套「養、套、殺」劇本重演**，而非單純視為新一輪正向布局訊號。這是全書對「歷史紀錄可信度」最直接的提醒——需要交叉比對該主力/該公司過去是否有「誠信瑕疵」的前科，不是所有「主力進駐」都值得跟單。
- **可程式化**: 否——需要先建立一份「券商-個股」歷史事件資料庫（記錄過去哪個券商分點在哪檔股票上，曾經在最高點大量出貨後股價腰斬），這需要長期(數年)的個股×券商分點交易史(`broker_chips`表，待FinMind付費方案)，且「事件偵測」本身（自動判定「最高點大量出貨後腰斬」算不算一次「事件」）也需要額外的門檻設計，是本清單中需要額外建立衍生資料結構、而非只是查詢原始資料的規則。
- **所需資料**: 個股每日各券商分點買賣張數（`broker_chips`表，待FinMind付費方案，且需要長期歷史累積才能形成有意義的「前科紀錄」）、股價歷史高低點（已有）。
- **計算公式**:
```
function detect_pump_and_dump_event(stock, trader, history_years=10):
    # 掃描長期歷史，找出「該券商在該股大量買進→股價高點→大量賣出→股價腰斬」的事件
    events = []
    for period in sliding_windows(stock, trader, history_years):
        if is_accumulation_then_distribution_at_peak(period) and price_halved_after(period):
            events.append(period)
    return events

function repeat_offender_discount(stock, trader, t):
    past_events = detect_pump_and_dump_event(stock, trader)
    if past_events and is_currently_accumulating(stock, trader, t):
        return "該券商在此股票有前科，本次進駐訊號可信度應打折扣"
    return "無前科紀錄"
```
- **參數**: 「最高點」「大量出貨」「腰斬」的精確門檻書中沒有給出量化定義，需自行設計並回測。
- **可回測**: 否——需要長期`broker_chips`歷史資料建立事件資料庫，短期內無法回測，是本清單中資料時間跨度需求最長的規則之一（與R-CHIP-19「已驗證主力資金轉移追蹤」同類）。
- **信心**: 15/100 低（方法論提醒很有價值，是全書對「歷史紀錄可信度」最直接的一課；但扣到低分是因為這條規則不只需要`broker_chips`資料源，還需要額外建立衍生的「事件資料庫」基礎設施，且需要長期歷史累積才有意義，距離可執行的落差是本清單中最大的之一）。
