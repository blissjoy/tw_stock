# SAR 實戰模擬分頁：實作進度與 Session 接手紀錄

最後更新：2026-10-22

## 目前狀態

已完成第一版可執行的 SAR 投組模擬核心，以及 PySide6「實戰模擬」分頁。可選日期區間、背景執行全市場歷史模擬、保存每次計算結果，重新啟動後載入最近一次紀錄，並顯示總資產摘要、未平倉部位及模擬事件。

階段一「歷史回測」已完成：同一固定策略分別在「較早期間／較近期期間」計算績效，提供每日資產變化及結果持久化，已使用本機實際行情驗證並通過完整測試。此功能用於比較不同歷史期間的模擬結果，不是未來預測。

階段二「未來情境推演」目前採下拉選擇大盤漲幅較大／接近平盤／跌幅較大其中一種路徑，每次只載入及推演單一情境。策略接續最近一次模擬的現金與未平倉，並列出所選路徑下逐日選出的股票及預計進場明細；情境績效和資產曲線為輔助資訊。可選 20／60／120 個交易日；結果存於獨立模擬資料庫。這是條件式假設推演，不是預測，也不代表情境發生機率。

## 已完成的程式變更

### `src/backtest/sar_portfolio.py`

- `SarStrategyParams`：第一版 SAR 篩選固定參數集中於策略內，未建立 `config/scanner_settings.json`，不改動全系統選股設定。
- `load_sar_market_data()`：從主資料庫讀取 `stock_prices`，連接 `daily_indicators` 既有的均線、SAR、翻多天數快取；保留沒有指標快取的行情列（這些列不符合選股，但仍可用於既有持倉價格更新）。
- `select_daily_sar_candidates()`：實作兩層條件、股／張單位換算門檻，逐日依 SAR 距離由接近 0 到較遠排序，每天最多留一檔。
- `run_sar_portfolio_simulation()`：共用現金、多筆持倉、隔日以當日最高價進場、現金不足跳過、加碼一次、停損、移動停利、逐日市值及未平倉處理。
- 每日事件包含選股、進場、加碼、加碼資金不足、資金不足跳過、停損出場、移動停利啟動與移動停利出場。
- 手續費：買進、加碼、賣出皆按 0.1425% 並套用最低 NT$20；買進費用列入持倉成本，賣出扣手續費及 0.3% 證交稅。費用目前以浮點精度計算，沒有取整到整數元。
- SAR 距離沿用 `src/presentation/chart_data.py` 的慣例：`(sar_value - close) / close * 100`。
- 無壓力區使用 `(close - MA60) / close > 0.03` 且 `(close - MA120) / close > 0.03`。2026-10-22 對照朋友的模擬結果時發現，初版公式方向相反，已修正並將策略版本升為 2；舊版本保存紀錄保留，但 UI 不再把舊策略結果當作目前結果載入，會提示重新執行。
- 移動停利保守日線順序：既有停利部位先用前一日峰值檢查出場；未出場才更新當日峰值。首次當日觸及 +16% 只啟動，不在該日再判定移動停利出場。
- 每個交易日先管理既有部位，再依前一交易日訊號新進場；同日出場現金可以支付新進場。
- 加碼價固定為原始買價的 85%；加碼後以含買進手續費的總成本／總股數計算均成本。加碼觸發但現金不足時，記錄跳過且不重試。
- 停損和移動停利出場以規則價成交；期末未平倉不強制賣出。

### `src/data/sar_simulation_storage.py`、`src/data/connection.py`

- 新增獨立本機 `data/sar_simulation.db`，可用 `SAR_SIMULATION_DB_PATH` 改路徑；資料庫有模擬 run 摘要、持倉快照與事件明細三張表，不會寫入主行情 DB 或 `portfolio.db`。
- 每次重算建立新的 run ID 並保留舊紀錄；保存交易參數 JSON，可按 run ID 或讀取最新 run 還原結果。
- 保存 run 與所有持倉／事件使用單一 SQLite transaction；主鍵衝突或寫入錯誤會回滾，不留下部分紀錄。

### `desktop/main_window.py`

- 新增第七個分頁「實戰模擬」，分頁索引為 `TAB_SAR_SIMULATION = 6`；原「回補資料」「日誌」索引順延。
- 日期預設為資料庫最新行情日前一年至最新行情日，可自行修改起訖。
- 執行按鈕讀取行情並重算，顯示本金、現金、持倉市值、總資產、已實現／未實現損益，以及持倉和事件清單。
- 結果區分為「目前持倉」、「已實現損益」及「模擬事件」子分頁；已實現明細列出訊號、進場／出場日期、均成本、出場價、淨損益及原因。
- 三張結果表皆可點欄位標題排序；每次載入結果預設將未實現／已實現損益數值降冪，模擬事件日期降冪。
- 模擬本金及選股收盤價上限可於畫面編輯，執行時傳入策略並寫入該次 run 設定，重啟後由最新同策略紀錄還原；摘要下方獨立顯示總報酬率，非負紅色、負值綠色。
- 新增零股／整張 radio：零股維持 NT$10,000 初始預算、NT$5,000 加碼預算；整張固定每次 1,000 股進場及加碼，資金不足跳過；交易模式一併保存並於載入紀錄時還原。
- 分頁使用主行情資料庫讀取；不連接或寫入 `portfolio.db` 真實庫存資料。
- 建立視窗時載入模擬 DB 最新紀錄；每次「執行模擬」使用專用 `SarSimulationWorker(QThread)` 另開行情與模擬 DB 連線，在背景讀資料、計算與保存，不阻塞 UI。
- 執行中停用按鈕並顯示狀態；失敗時呈現錯誤且不覆蓋先前成功的紀錄。

### 階段一：歷史回測

- `src/backtest/sar_portfolio.py`：新增每日投組資產快照；歷史資料由 OHLCV 在記憶體重算均線及 SAR，避免依賴不完整的 `daily_indicators` 快取，行情 DB 以唯讀方式使用。
- `src/screener/indicator_precompute.py`：增加可選 `include_trend_position=False`，只需 MA/SAR 的驗證略過無關的趨勢位置運算；預設值仍維持原本完整欄位。MA/SAR逐日取值改用 NumPy 陣列以降低長區間重算成本，計算結果沿用既有演算法。
- `src/backtest/sar_validation.py`：固定規則下比較嚴格先後且不重疊的前段／後段歷史期間；兩期各自以相同本金重開，不做參數最佳化。計算訊號、平倉、勝率、已實現／未實現／總損益、報酬率、最大回撤、平均持倉市值／初始本金及 0% 現金基準。
- `src/data/sar_simulation_storage.py`：新增 `sar_historical_validations`，以 JSON 保存回測設定、兩期期績效及較近期期間每日資產曲線；既有策略模擬 run 保持不變。
- `desktop/main_window.py`：將「實戰模擬」整理為「策略模擬／歷史回測」內層分頁；回測可調日期、本金、股價上限、零股／整張，顯示兩段績效表及較近期期間資產變化，並於啟動時載入最近一次回測結果。資料限制警告包含現有股票清單造成的存活者偏差、未還原除權息，以及較近期期間含有曾用於規則比對的日期。
- 預設切分保留 240 個交易日暖身，其餘日期以前 70% 為較早期間、後 30% 為較近期期間；比例用整數運算避免浮點誤差。兩期不得重疊。

### 階段二：未來情境推演

- `src/data/sar_simulation_storage.py`：新增 `sar_forward_scenarios`，保存起始 run、來源區間、情境績效與每日資產曲線，支援載入最近一次情境結果。

## 已確認的策略規格／計算順序

1. 訊號日收盤後每日最多選一檔，依 SAR 距離 `|距離%|` 越接近 0 越優先。
2. 下一交易日以當日最高價進場，初始買入股數 `floor(10,000 / 買價)`；費用另計。現金需足以支付成交金額與手續費，否則跳過、不排隊。
3. 已持倉部位每日依序：觸發加碼（NT$5,000，原始買價 × 0.85，僅嘗試一次）→停損（均成本 × 0.80）→既有移動停利檢查（前一日峰值報酬減 3 個百分點）→更新當日峰值並檢查 +16% 啟動。
4. 既有持倉先管理及出場，再處理前一交易日訊號的當日進場；當日回收現金可用於新進場。
5. 期末部位保留為未平倉，按最後可用收盤價計算市值及未實現損益。
6. `stock_prices.volume` 單位是股：基本門檻 10 張 = 10,000 股，策略門檻 1,000 張 = 1,000,000 股。
7. MA60、MA120 壓力差距各自須高於收盤價 3%；SAR 演算法重用 `src/indicators/parabolic_sar.py` 既有計算結果，不另寫 SAR。
